# Critical Path Analysis

## Overview

Critical Path Method (CPM) was used in the Residential Construction Project to identify the sequence of activities that determines the project's minimum planned duration.

The analysis considered activity duration, early start, early finish, late start, late finish, and float.

---

## Critical Path

Activities on the critical path had zero float in the project analysis.

This means that a delay to one of these activities could directly affect the overall project completion timeline.

The analysis began with the project start and followed the dependent sequence of construction activities through to the later stages of the project.

---

## Key Scheduling Concepts

| Concept           | Application                                                            |
| ----------------- | ---------------------------------------------------------------------- |
| Activity Duration | Estimated time required to complete an activity                        |
| Early Start (ES)  | Earliest point at which an activity can begin                          |
| Early Finish (EF) | Earliest point at which an activity can finish                         |
| Late Start (LS)   | Latest point an activity can begin without delaying the project        |
| Late Finish (LF)  | Latest point an activity can finish without delaying the project       |
| Float             | Allowable scheduling flexibility before project completion is affected |
| Critical Activity | Activity with zero float on the critical path                          |

---

## Relationship with the Gantt Chart

The critical path analysis complemented the Gantt Chart.

The Gantt Chart provided the planned timeline and task sequence, while the critical-path analysis identified activities with no scheduling flexibility.

Together, these tools supported:

* identification of schedule dependencies
* understanding of activities that could affect completion
* prioritisation of schedule monitoring
* project-duration analysis
* identification of potential schedule risk

---

## QA Perspective

From a Quality Assurance perspective, schedule information needed to remain consistent across the project's planning documents.

My documented QA activities included reviewing the Gantt Chart and checking duration accuracy.

This reinforced the importance of validating schedule information before finalising project documentation.

---

## Key Learning

The critical path demonstrated that not every project activity has the same impact on completion.

Activities with zero float require closer monitoring because delays can propagate through dependent activities and affect the overall project timeline.

This strengthened my understanding of how scheduling information can be used as a project-control mechanism rather than simply as a visual timeline.
