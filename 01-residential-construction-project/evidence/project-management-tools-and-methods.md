# Project Management Tools & Methods

## Overview

The Residential Construction Project applied a range of project-management tools and methods to plan, coordinate and control the project.

These tools were not used independently. They supported different stages of the project lifecycle and provided inputs to other project-management activities.

---

## Core Tools and Methods

| Tool / Method | Purpose | Project Application |
|---|---|---|
| Project Charter | Establish project direction | Defined objectives, scope, stakeholders, risks and project parameters |
| Scope Statement | Define project boundaries | Identified inclusions, exclusions, deliverables and constraints |
| Work Breakdown Structure (WBS) | Decompose project work | Structured project deliverables and activities |
| Network Diagram | Establish task relationships | Supported sequencing and dependency analysis |
| Gantt Chart | Develop and monitor schedule | Documented activities, durations, dates and progress |
| Critical Path Method | Analyse schedule constraints | Supported identification of activities affecting project duration |
| Risk Register | Identify and assess uncertainty | Recorded risks, likelihood, consequence and treatment |
| Resource Plan | Allocate project resources | Connected personnel and resources to project activities |
| Cost Plan | Support financial planning | Connected resource requirements with project costs |
| Stakeholder Register | Identify project stakeholders | Supported stakeholder prioritisation and engagement |
| Communication Plan | Define information flows | Established audiences, frequency, methods and responsibilities |
| QA Checklist | Verify deliverable quality | Supported accuracy, formatting, referencing and consistency |
| Version Control | Maintain document traceability | Recorded revisions to project documents |

## Scheduling Methods

The project used both network-based planning and Gantt Chart scheduling.

### Network Diagram

The network approach focused on relationships between activities and dependencies.

It supported analysis of:

- Activity sequence
- Predecessors
- Successors
- Earliest and latest activity timing
- Schedule flexibility
- Critical activities

### Gantt Chart

The Gantt Chart translated project activities into a time-based schedule.

Relevant fields included:

- WBS reference
- Activity description
- Planned duration
- Start date
- End date
- Predecessor / successor relationships
- Actual duration
- Percentage completion

Using both approaches provided complementary views of the project schedule.

## Risk Management Method

Risk management followed a structured process:

**Identify Risk**  
↓  
**Assess Likelihood and Consequence**  
↓  
**Determine Risk Rating**  
↓  
**Develop Treatment / Mitigation**  
↓  
**Monitor Risk**  
↓  
**Reassess When Conditions Change**

This approach allowed risks to be connected to project planning rather than treated as isolated issues.

## Change and Version Control

Project documents were developed iteratively.

Version control helped distinguish revisions and supported traceability as information changed.

Examples included revisions to:

- Team Charter
- Scope documentation
- Risk Register
- Gantt Chart
- Resource and Cost Plan
- Final project documentation

This approach reflects an important engineering principle: project information should remain traceable as requirements, plans and deliverables evolve.

## Key Learning

The main lesson from using these tools was that each tool provides only part of the project picture.

For example:

- The WBS defines the work.
- The network diagram defines relationships.
- The Gantt Chart defines the timeline.
- The risk register identifies uncertainty.
- The resource plan identifies required resources.
- The communication plan defines information flows.
- QA helps maintain the quality and consistency of project information.

The value comes from **integrating these tools**, rather than treating them as separate administrative documents.
